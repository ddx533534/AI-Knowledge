# 有限次访问码的事务扣次与幂等设计

<!-- AI:BEGIN -->
## 结论

有限次测评码用临时预留控制并发开始，在同一事务保存结果、写唯一账本、扣次及完成轮次。本项目已在本机PostgreSQL 17.11验证重复提交、并发开始和故障回滚；验证范围为本地实现，生产环境未部署。

## 关键发现

- 开始仅预留，完成成功才消耗；预留过期、恢复和取消需要在同一码锁内处理。
- 成功账本与结果对attempt分别唯一，HTTP响应丢失后重试同轮返回原报告而非再扣一次。
- 码行先锁、attempt行后锁，各路径统一顺序；计数上限与唯一约束不能由按钮状态替代。
- 批量100码须整批事务与管理请求幂等，导出失败不能默认新增一批。
- 使用真实PostgreSQL完成本地并发/幂等/回滚测试；不能把SQLite或本地测试成功扩展成生产验收结论。

## 证据与分析

旧技术方案第4—5节为设计证据；新增实施记录第3—4节为实际实现和测试证据。10路相同轮次并发提交只生成一个结果、扣一次；8设备同时开始只有3个成功；注入存储异常后结果、账本和次数全部回滚。17项本地测试通过，不代表云端数据库权限、网络、运行时已验收。

- 上线前在实际云端PostgreSQL复验同一并发与回滚场景。
