# Strands Box 与操作系统沙箱

<!-- AI:BEGIN -->
## 结论

历史调研把 Strands Box 描述成结合操作系统隔离与策略检查的 Agent 沙箱：程序能直接碰到的范围由 box.toml 在启动前固定，其余请求走受信任组件的检查路径。本文解释这套来自归档材料的设计机制，当前实现与平台保证未重新核实。

## 关键发现

- 直接访问范围由 box.toml 声明并在启动前固定，越出范围的操作不能由程序自己发起。
- 直接访问与通过受信任组件请求代办操作走不同的检查路径：policy.dw 检查的是经由 Box 处理的请求。
- 原报告记载，已获准直接访问的文件不会逐次进入代办请求的策略历史。
- 历史 README 的本地预览声明只覆盖 macOS Apple silicon，不能据此推断其他平台保证行为一致。

## 证据与分析

依据归档报告 S1、S3 的原文摘录。资料标注 Box 0.1.0、来源 commit `331d563e8599b4359f9578ea377fc4f2d0dccce7`，原核实日期为 2026-10-09，且报告本身写明没有运行过 Box。同一份历史报告里同时出现 Linux 后端与 macOS 本地预览的记载，这只能说明代码里有对应实现，不能证明两个平台行为一致。本次只读取归档材料，不声明重新验证源码或运行效果，也不把这两条路径的机制泛化成所有沙箱的实现方式。
