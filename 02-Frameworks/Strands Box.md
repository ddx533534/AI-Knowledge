# Strands Box

<!-- AI:BEGIN -->
## 一句话定义

Strands Box 是 AI Agent 的安全沙箱：让 Agent 能干活，同时把它能访问和影响的范围限制在配置与策略允许的范围内。[S1]

## 解决的问题

Agent 可以读文件、改代码、执行命令和访问网络。Box 假定 Agent 可能受到恶意指令影响，把安全限制放在 Agent 自己的判断之外。[S2]

可以把 Box 想成一个受管理的工作场所：Agent 提出请求，操作系统限制活动范围，Box 的处理组件按规则办事。[S1、S5；解释性比喻]

## 核心机制

### 两种限制各管一条路径

| 配置 | 通俗理解 | 负责什么 |
| --- | --- | --- |
| `box.toml` | 直接活动范围 | 程序能直接读取、写入哪些路径，以及运行哪些程序等 |
| `policy.dw` | 请求 Box 代办的规则 | Shell、Python、网络和 MCP 请求在什么条件下允许 |

程序直接访问文件时，由操作系统检查。通过 Box 请求操作时，由策略引擎检查。**直接获准读取的文件，不会再逐次经过策略判断。** 两条路径共同决定程序能做什么。[S3]

### 组件怎样配合

| 组件 | 通俗理解 |
| --- | --- |
| 操作系统沙箱 | 限制 Agent 和工具自己能直接接触什么 |
| Strands Shell / Monty | 处理 Shell 命令与 Python 脚本，把受管理的操作交给检查入口 |
| 网络网关 | 检查网络请求，并处理配置好的凭证 |
| MCP broker | 检查并转发本地 MCP 服务请求 |
| 策略引擎 | 统一判断允许或拒绝，保存请求历史 |
| 日志组件 | 记录决定及相关原因 |

依据：[S3、S5、S6、S7]。主要关系可以这样记：

```text
Agent 直接操作 → 操作系统检查直接权限
Agent 请求 Box → Shell / Python / 网关 / MCP → 同一个策略引擎
启动外部工具 → 先判断是否允许启动 → 工具各自的沙箱
```

一个 `strands-box run` 管一个 Box。主要处理组件和策略引擎运行在 Agent 沙箱之外；Shell 和 Python 的解释器状态按请求创建，不跨请求保留。[S5]

### 规则怎样生效

经过策略检查的请求默认拒绝；匹配的允许规则才能放行，禁止规则优先。Shell、Python、网络和 MCP 共用一个引擎和一份历史，因此可以写“通过 Box 读取某文件后，五分钟内拒绝某类网络请求”的规则。历史只能使用经过策略的事件。[S1、S3、S4]

Box 管理的真实凭证保存在受信任进程中，由网关用于符合目的地配置和策略的请求。配置凭证不会自动获得访问许可；同一 Box 内的程序共享凭证路线。[S6、S8]

### 一个具体例子

Agent 请求 `zsh -c 'echo hi > notes.txt'`，Box 的 Shell 检查实际命令和目标文件写入，检查通过才执行。允许命令不等于允许所有文件操作。[S14；文档示例，本次未实测]

`git`、`cargo` 等外部程序由 Box 启动时走另一条路径：判断启动权限后，在自己的沙箱里运行。它们内部的文件访问不会逐次产生 `fs:*` 策略决定。[S7]

## 取舍与局限

- 允许操作仍可能违背任务意图，例如允许写文件后，Agent 仍可能清空内容；Box 不会在退出时自动撤销修改。[S9]
- Agent、工具和本地 MCP 服务的直接文件访问不会自动进入策略历史。[S3、S7、S9]
- 主动开放凭证文件或给解释器过宽的文件规则，仍可能暴露秘密。[S3、S9]
- 工具或本地服务的显式网络例外可以绕过网关；网关检查并非覆盖所有配置情形。[S6]
- 沙箱外的处理组件需要被信任；其缺陷以及宿主内核漏洞不由 Agent 沙箱隔离。日志交付也不具备防篡改与零丢失保证。[S5、S10]

使用时应同时检查直接权限与代办规则，只开放任务需要的范围。[S3、S9；由已核实边界得到的配置建议]
