## 写法约定

### 深度标准（2026-10-14 起）

不追求「每个点都提一句」，只挑面试会一路追问到底的题，每个点讲透三层：

1. **机制层**——内核/源码里到底怎么做的。能说出**函数名、常量名、字段名**（如 `expireIfNeeded`、`TCP_TIMEWAIT_LEN`、`rehashidx`、`DB_ROLL_PTR`），不只是名词。
2. **证据层**——引用**一手依据**：Linux 内核源码与 `ip-sysctl.rst`、RFC 编号、Redis/MySQL 源码文件、官方文档、论文。**不再以 CSDN/博客为来源**。
3. **追问层**——每个点配「面试官会怎么一路追问」，逐层递进给答案。

其他要求：能算的当场算（扇出、端口 QPS、RTO 退避）；主动写「常见误区」与「边界」（RR 不是完全消除幻读、HTTP/2 没解决队头阻塞）；参数与源码位置注明**版本差异**。

### 格式约定

- 每篇按「结论 → 深水区逐题展开 → 高频追问速查（面试官问/我答）→ 建议 → 待核实 → 来源」组织。
- 图一律自己画成 SVG，放在 `assets/<日期>/` 下，浅色扁平、细边框、颜色只承载含义不承载装饰。
- **同一天有多份文档时用 `assets/<日期>-<主题短名>/`**，避免多篇文档的 `figN` 撞号。
- 拿不准的写进「待核实」，不编造。术语保留英文原文（如 TIME_WAIT、MVCC、TLB），中文只做叙述。
