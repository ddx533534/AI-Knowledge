问题 怎么修 根因落点（代码级） 代价与注意
scroll_view 隐藏再显示后滚动位置被重置 改两处：ScrollView 的 onLayoutChange 里加「子布局宽高为 0 就跳过」的判断，不要在这个状态下写回位置；HorizontalScrollView 压根没保存过位置，补上与 ScrollView 一致的保存逻辑 布局回调在子视图还是 0×0 时就把位置写回去了 滚动动画进行中同时发生布局变化时，理论上可能直接跳到目标位置、动画失效；RN 最新版采取了类似处理（isContentReady()，见 4.1）

子元素溢出父元素无法点击 事件自上而下分发，中间那层容器判定「子树不含触点」就不再往下走。两条路：① TouchDelegate 把父容器热区代理给子视图；② 重写 dispatchTouchEvent 与 onInterceptTouchEvent 自己分发 原生命中判定只认子视图自身的 bounds（ViewGroup.isTransformedTouchPointInView → child.pointInView），溢出部分天然落空 ① 需要 recce-ui 新增设置触摸代理的方法；② 所有能当父容器的 view 都会受影响，影响面大。上游有第三条路（见 4.2）

3.1 隐藏 scroll_view 又不丢滚动位置

不用 visible 完全隐藏，改成「高度归零 + 全透明」，位置就不会被布局重置带走：

styles! {
  fake_invisible { Height::number(0.)  Opacity::number(0.) }
  fake_visible   { Height::auto()     Opacity::number(1.) }
}

隐藏的是父布局时绕不过去，要用共享态存位置：隐藏前把当时的 offset 存下来，on_layout 里判断宽度从 0 变成正数时再恢复（用 animated: false 直接跳，不要放动画）：

on_layout: move |e| {
  if let Ok(d) = e {
    let w = frame.get().as_ref().width;
    set_frame(d.layout.clone());
    // 宽度从 0 恢复到大于 0，判定为「隐藏 → 显示」
    if w == 0. && d.layout.width > 0. { restore_scroll(); }
  }
}

3.2 图片 ResizeMode 不生效

在 on_load 里强制刷新一次高度，逼它重新按 ResizeMode 计算边界：

let height = use_state(cx, || Height::number(0.));
image {
  style: { ResizeMode::Stretch  {height} },
  source: "...",
  on_load: move |_| { height.set(Height::auto()) },
}

图片本来就是异步加载、从无到有，所以额外刷一次高度没有副作用。

3.3 MaxWidth/MaxHeight 用了 undefined

不要用 undefined，Android 会把它的值 0 当成最大宽高。需要「不限宽」时给一个极大值：

MaxWidth::number(200.)  Height::number(500.)  Width::auto()

{toggle}.map(|v| match *v {
  true  => MaxWidth::number(99999.),   // 等价于「不限」，不要写 undefined
  false => MaxWidth::number(200.),
})

适配所有版本，代价是不美观。

3.4 部分机型 Label 裁最后一个字

显式指定字体，不再依赖机型默认字体：

label {
  style: { FontSize::number(14.), FontWeight::N500, FontFamily::new("system") },
  text: "+ 添加新卡",
}

3.5 foreground 回调触发不稳定

先判断当前 Native 版本有没有这个能力（recce_ui 0.13.6+ 提供 can_i_use），没有就绕到 MSI 的广播上：

if env().os == OS::ANDROID && !can_i_use::android_foreground() {
  use_future!(scope_id, async move {
    // 先随意调一次 MSI 桥，触发 MSI 挂载
    let _ = MSI::subscribe("onAppStatusChange", None, |_, _| {}).await;
    add_app_listeners(AppEventListener::new(
      "onAppStatusChange".to_string(),
      move |event: &AppEvent| { /* app_status 为 Foreground 时做事 */ },
    ));
  });
}

更省事的替代：直接用 appear 事件代替 foreground。

3.6 env 取不到 window 尺寸

Android 的 display_width/height 实际给的是 window 值，而 window 尺寸双端都没传。业务侧用 MSI 桥自己取（MSI 接口 id 1504）。

3.7 1.32 以下的 visible_area_change

两个 rect 各坏一个，业务侧可以互补计算；老版本返回 px，记得除 pixel_ratio 换成 dp：

if env().os == OS::ANDROID && !can_i_use::android_visible_area_change_data() {
  let ratio = env().pixel_ratio.unwrap_or(1.);
  // Android 用 interactionClientRect + ScrollView 相对原点偏移；iOS 用 boundingClientRect 减偏移
  let right = env().display_width as f32 - (rect.x as f32 + rect.width as f32) / ratio;
  let top   = rect.y as f32 / ratio + rem(10.) - panel_top;
}

3.8 input placeholder 折行

像 web 一样自实现一层 placeholder：input 外面套相对定位容器，再叠一个绝对定位的 label，文本为空时显示占位文案：

view {
  style: { Position::Relative }
  input {
    style: { Width::number(100.), IncludeFontPadding::bool(false), NumberOfLines::s32(1), TextAlignVertical::Center }
    on_change_text: move |t| text.set(t),
  }
  view {
    style: { Position::Absolute, Top::number(0.), Bottom::number(0.), Left::number(5.), AlignItems::Center }
    label { style: { NumberOfLines::s32(1), Color::rgb(0xcccccc) }, text: {is_visible}.map(...) }
  }
}

3.9 父级整体透明

Android 无法整体变浅，用与背景同色的遮罩层模拟：在最外层加一个 absolute、四边贴合、与背景同色的视图，把 Opacity 设在遮罩上。

四、技术思路与业界方案

上面给的是「怎么修」，这一章补三件事：根因落在代码哪一层、上游在同一位置怎么实现、有没有现成更优的路。出处全部是公开上游源码与规范（2026-10-14 抓取）。

4.1 四条值得记住的机制

① display:none 在 Yoga 里就是「整棵子树归零」。 上游源码中 Display::None 走 zeroOutLayoutRecursively()：把该节点 layout 清空、宽高显式置 0、标记 hasNewLayout，然后递归对全部子节点做同样的事。所以「隐藏 = 自身与所有子视图变 0×0」是引擎的官方语义，不是 Android 端的怪癖 —— 五章第一条通则的问题根在这里。同一处历史上与 absolute 定位冲突（绝对定位又算出真实尺寸，盖掉了 0×0），上游由 PR #1068 修复。出处：CalculateLayout.cpp 的 zeroOutLayoutRecursively。

② 「未定义」的正规表示是 NaN，不是 0。 YGUndefined 的定义就是 quiet_NaN()；现代 Yoga 把尺寸包成 StyleSizeLength / StyleLength（FloatOptional + Unit），undefined() 是一个合法状态，传入 NaN 会被归一成 Unit::Undefined。也就是说「不限宽」在这套类型系统里有位置，被解析成 0 属于解析层丢了信息 —— 2.1 最后一条那个「把 0 改成 NaN」的兜底，方向与上游一致。出处：YGValue.h、StyleSizeLength.h；另注 YGFloatOptional 已改名 FloatOptional（#39196）。

③ ScrollView 的 250ms 有两个来源，而且方法不可重写。 AOSP ScrollView.smoothScrollBy 声明为 public final（子类改不了），函数体里 ANIMATED_SCROLL_GAP = 250：距上次滚动 ≤250ms 时直接 mScroller.abortAnimation() 再 scrollBy，表现上正是「animated 被当成 false」；OverScroller.DEFAULT_DURATION 同样是 250。出处：ScrollView.java、OverScroller.java。这解释了 2.2 第二条为什么「改系统源码」那条路够不到 mFlingSpan 以外的东西。

④ RN 对③选的是「不用 OverScroller」，而且装的是普通插值器。 RN 的 ReactScrollViewHelper.smoothScrollTo 不走 smoothScrollTo，而是对 scrollY 起一个 ObjectAnimator（defaultFlingAnimator），时长由 OverScrollerDurationGetter 反射读 AOSP 默认值兜底；ReactScrollView 里明确注释「smoothScrollTo is final，所以我们另开 reactSmoothScrollTo」。注意 RN 并没有设置自定义 Interpolator，用的是 ObjectAnimator 默认的加速减速 —— 2.2 第二条的路 ② 落到代码上就是这个形态，不必自己写插值器。出处：ReactScrollView.kt、ReactScrollViewHelper.kt。

⑤ 「宽高为 0 就不写回滚动位置」是 RN 的既有实现。 ReactScrollView.onLayout 只在 isContentReady() 为真时才滚到 pending 值，而 isContentReady() 的实现就是 child != null && child.width != 0 && child.height != 0；内容未就绪时目标位置被暂存为 pending。该逻辑由 commit 4846f1b 引入、be260b9 修过，iOS 侧 47903d0 是明确对齐 Android 的对等实现。2.2 第一条的修法与它同源。

4.2 业界在同一位置怎么做

我们这件事 上游/业界现在的做法 差异在哪 能不能借鉴
子元素溢出父元素点不到（2.2 第三条） RN 另建了一层命中判定：TouchTargetHelper 自根向下 DFS，逐层判 pointerEvents 四个值、hitSlop、overflow 与 clipChildren、transform 矩阵求逆；原生分发照旧。专门修「父容器外的子视图可点」的上游 commit 是 e35a963（#29039） 我们动的是 Android 原生分发链（dispatchTouchEvent / onInterceptTouchEvent）；RN 不动原生分发，只在「事件该给谁」这一层自己算 值得。RN 那层是独立的纯判定函数，改动面收在一个文件里，不必替所有能当父容器的 View 兜底 —— 正是路 ② 的风险所在。代价是自己维护一套与 pointerEvents / hitSlop / overflow / transform 对齐的判定，并跟着属性协议演进。出处：TouchTargetHelper.kt
父容器抢手势（2.3 第三条） RNGH 3.3.0 的 NativeViewGestureHandler：用 view.onInterceptTouchEvent() 判断是否该激活，包裹时调 requestDisallowInterceptTouchEvent(true)，子手势再用 blocksExternalGesture 反向压制父滚动容器；「可否被抢占」由 disallowInterruption 显式声明 我们用 rui 的 event_bus 直接派发事件，绕过 native 手势识别 借它的判据而不是实现：「父容器可否被抢」应该是子视图声明出来的属性，而不是靠换一条事件通道绕过去。我们升到 on_touch_end 已是同一方向。出处：RNGH Native gesture
前后台状态（2.4 foreground） RN 的 AppStateModule 实现 LifecycleEventListener（onHostResume→active、onHostPause→background）与 WindowFocusChangeListener；Android 官方推荐的「整个应用前后台」判据是 androidx.lifecycle.ProcessLifecycleOwner + DefaultLifecycleObserver，ON_STOP 会延迟 700ms 派发以覆盖配置变更引起的 Activity 重建 我们退到订阅 MSI 广播 值得。ProcessLifecycleOwner 的语义就是整个进程的前后台，比订阅广播稳；注意它在多进程下不知道其他进程，也不追求毫秒级精度。出处：AppStateModule.kt、ProcessLifecycleOwner.kt
env 的窗口尺寸（2.4 第三条） Android 官方口径：多数场景用 getCurrentWindowMetrics()（API 30+，非全屏也正确），返回的 bounds 不扣除 WindowInsets 需自减，密度取 Configuration#densityDpi；Display.getSize / getRealSize 分别自 API 30 / 31 弃用。RN 的 DeviceInfoModule 走 Jetpack WindowMetricsCalculator.computeCurrentWindowMetrics，取不到才回落 resources.displayMetrics，屏幕尺寸另走 screenPhysicalPixels 我们只下发了一套值，取到的是 window 值却当屏幕值用 值得。窗口与屏幕本就是两套量，上游是分开下发的。出处：WindowManager、多窗口适配、DeviceInfoModule.kt
1px 边框与三边 borderWidth（2.1） RN 在 Android 不做特殊取整：borderWidth 经 PixelUtil.toPixelFromDIP（TypedValue.applyDimension）直接转像素，不 ceil / round；但 RN 在 PixelRatio.js 里写明「一个取整误差就足以让 1 像素边框消失或变成两倍宽」，并给业务侧提供 PixelRatio.roundToNearestPixel() 我们错在布局层（三边没写进 Yoga 节点），RN 的坑在绘制层的像素取整 两者互补：布局层四边都要写全，样式层按 roundToNearestPixel 取整。npm 上并没有 react-native-hairline 这类包（registry 返回 Not Found），社区文章里的包名不要照抄。出处：PixelUtil.kt、PixelRatio.js
图片 ResizeMode（2.1） RN Android 侧可选值是 contain/cover/stretch/center/repeat/none（映射到 Fresco ScaleType），绘制层默认 CENTER_CROP，JS 层两端默认值都是 'cover' 我们双端默认值不一致；Android 侧取值域也更窄 默认值直接对齐 cover；取值域差异写进属性协议（缺 fit_start / fit_end 属取值域问题，RN 也没有这两个值）。出处：ImageResizeMode.kt、Image.android.js
双端无障碍（2.4 第四条） RN 的 accessible 在 Android 翻译成原生 focusable、iOS 翻译成 isAccessibilityElement；accessibilityElementsHidden（iOS）与 importantForAccessibility="no-hide-descendants"（Android）等价；aria-hidden={true} 在源码里就是同时写这两个 我们两端各写各的，语义分散在业务里 值得。把平台差异收进框架层翻译，业务侧只表达「要不要被辅助服务看见」。出处：RN 无障碍、View.js

曝光与可见性那一条不在这里展开，见《RN-IntersectionObserver-与-Recce-曝光方案对比》；布局引擎的选型见《Recce-Yoga-升级方案复盘》。

五、三条通则

  • 差异未必是「一端对一端错」。AlignSelf 是 Recce 解析反一次、iOS 又反一次，两次抵消后只有 Android 错 —— 只看两端结果会把根因判错。定位跨端差异要拿 RN 的行为当第三参照。
  • Android 的「隐藏」是一次真实的布局塌缩。display:none 按引擎语义就是自身与整棵子树归零（4.1 ①），滚动位置、自适应高度、传给宿主的组件尺寸这些从尺寸派生的量都会被这个 0 污染。原始材料记「Android 会展开到全部子视图、iOS 只改自身」，按引擎语义 Android 才是标准行为，iOS 那一侧是否属实现偏差未核实（见第六章第 7 条）。凡「隐藏后再显示状态丢失」，先查这条链，不要先怀疑隐藏属性的实现差异。
  • 属性协议要写清四件事，这批问题里四件各出过一次：默认值（双端 ResizeMode 默认值不一致）、取值域（Android 侧 ResizeMode 只支持四个值，fit_start/fit_end 没有）、单位（1.32 以下 interactionClientRect 返回 px 而不是 dp）、参照系（同一次曝光，Android 相对屏幕、iOS 相对 scroll_view）。机型类差异的 hack 全是「显式声明」，修的时候要把「依赖某个机型默认值」换成结构性条件，否则换机型就复发。
