# 知识规范

Markdown 笔记是知识与关系的唯一可信存储。派生索引可以重建，不在索引中直接维护独立事实。

写入语言与表达方式遵守 [[99-System/调研与分析输出规范]]。正文、章节、说明和摘要统一使用中文；官方技术名称、代码及机器字段保留原样。

## 分类与名称

- 概念/协议放 `01-Concepts`，框架/模型/运行时/工具放 `02-Frameworks`，架构放 `03-Architecture`，对比放 `04-Comparisons`。
- 新建前搜索文件名、title、aliases、已有正文与来源。规范名使用官方名称；中文名、缩写和旧名写入 aliases。
- 文件名与 title 一致；链接优先使用 Vault 相对完整路径，例如 `[[01-Concepts/MCP|MCP]]`。实际目标不存在时不得创建链接。
- 名称与别名冲突只是重复候选，需核实语义再合并；不要擅自合并同名但不同含义的技术。

## 知识节点字段

使用 YAML frontmatter：

| 字段 | 规则 |
| --- | --- |
| `title` | 非空规范名，与文件名一致 |
| `type` | concept / protocol / framework / model / runtime / tool / architecture / comparison |
| `aliases` | 字符串列表，无别名时为 `[]` |
| `status` | verified / partial / unverified，表示证据核实状态，非用户掌握程度 |
| `created`、`updated` | `YYYY-MM-DD`，记录真实创建/实质变更日期 |
| `last_verified` | 最近真实核实来源的日期；未核实为 `null` |
| `sources` | HTTP(S) 来源地址，或可访问的 `vault:相对路径` 证据；本地源码摘录先保存到调研报告，并记录原始路径、版本及行号 |
| `relationships` | 有直接证据的关系对象列表，无关系时为 `[]` |

知识节点的正文依次为“结论、关键发现、证据与分析、建议”，AI 区域外保留“人工笔记”。结论用 1～3 句解释这是什么、解决什么问题、适用条件；关键发现最多 3～5 点，保留核心机制、重要取舍及其影响；证据与分析只保留支撑结论的事实、技术关系及必要限制，区分事实、推断和未知；建议给出具体应用或核实步骤。不同类型节点按实际问题选择内容，不为了填满模板堆砌。

每条重要事实在正文附来源编号/链接，或标“未核实”；不能只罗列一组来源而不说明支持什么。细节、完整源码位置和原始资料放可选“附录”，正文遵守规范的篇幅控制。

来源无法获取或不能支撑结论时，保持 unverified/partial 并说明未知。last_verified 不因修改格式或重新生成索引而刷新。来源冲突时并列记录版本、时间和分歧，不任选其一补全事实。

## 关系对象与正文

每个 relationships 对象使用 target、type、explanation、sources。target 是存在的知识节点路径，type 取 [[99-System/关系类型]] 中的值，explanation 解释关系，sources 列直接证据。

正文“证据与分析”还需写同一目标的 wikilink、关系类型、中文解释和证据编号，使 Obsidian 能建立边。工具检查目标存在及正文链接，但不验证证据语义，也不自动补写正文。

待核实关系仅以普通文本写入“证据与分析”并标为未知，不加入 relationships，不使用 wikilink；证据核实后再加入图谱。

## 人工内容保护

自动化只改一对 `<!-- AI:BEGIN -->` / `<!-- AI:END -->` 之间的正文；frontmatter 中只合并受维护字段，保留其他人工属性。`## 人工笔记` 和其他 AI 区域外内容原样保留。

旧笔记没有 AI 标记时，先理解现有内容，只追加新的 AI 区域或提出具体合并建议；有冲突时保留双方和不确定性。不以模板替换整篇旧笔记。

## 调研、缺口与日志

调研报告同样采用“结论、关键发现、证据与分析、建议”。结论直接回答已确认的问题并说明适用范围；正文保留核心证据、推断、未知及影响决策的反面证据。实际读取资料、版本/核实日期、源码位置和已整理节点放在证据段或附录。重复调研复用旧报告或按真实版本/问题差异创建新报告，不按每次运行机械新增。

知识缺口也采用四段正文：结论说明具体未知与影响，关键发现说明待解问题的重要性，证据与分析列已有证据和用户掌握程度未知，建议列可执行核实步骤及建议来源；相同主题复用原记录。没有证据时不替用户推断学习水平。

新增、更新、关系变化和真实失败写入 [[99-System/变更日志]]；无变化不重复记日志。完成后校验并重建派生索引。既有人工问题与本次引入的问题分开报告。
