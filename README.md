# 技术知识库

提炼技术知识、记录工作实践、跟踪 AI 行业动态。日常阅读从 [首页](首页.md) 进入。覆盖所有技术主题。

| 目录 | 用途 |
| --- | --- |
| `01-Knowledge` | 提炼后的技术知识，一个主题一个文件 |
| `02-Work-Practice` | 工作中真实遇到并解决的问题的实践记录，含插图 |
| `03-Daily` | 每日 AI 行业简报与单个仓库分析，含插图 |
| `.obsidian` | 编辑器配置 |

## 使用方式

本机知识库路径：`/Users/dudongxu/Desktop/codex/AI-Knowledge`（2026-10-12 由 Windows 机器的 `E:\AI-Knowledge` 迁入）。在 Obsidian 打开本目录，从 [[首页]] 浏览。

每个目录的写法与文件约定写在各自的 `README.md` 里：

- `01-Knowledge`：同类主题合并进同一份文件，旧标题保留在 aliases 里当检索入口；不为一件事建多份文件，也不做「一段短文 + 一个指向原文的链接」这种双层结构。
- `02-Work-Practice`：只收自己参与的实际工作里遇到的问题；原始材料留在各自源头，文档写的是对照后的结论。对照与复盘类内容用表格，不写成段叙述。
- `03-Daily`：每天一份日报，同日补充的核实内容追加到当天文件，不新建文件、不覆盖原有结论；每份配 3 到 6 张图。

真实性纪律、关系证据要求与技术内容准入标准见 [AGENTS.md](AGENTS.md)。

## 技术内容准入（2026-10-11 用户明确要求）

提炼成知识节点前必须阅读正文并判断研究对象，不能凭“调研”“总结”“分析”、research/analysis 标记、项目名称或出现代码就收录。

- 仅收录以软件、算法、系统、协议、工程技术或其他技术机制为主要对象，且包含可复查技术证据的调研、探索、架构、技术对比和故障调查结论。
- 非技术性的调研、总结、分析不提炼、不建文件。明确排除题库与结果文案、叙事身份设计、心理测量与用户访谈方案、营销、运营、商业策划与一般内容创作。
- 混合文档以主要研究对象判断；非技术文档夹带少量计分规则、脚本或测试记录仍排除。已有独立技术研究文档时仅收录该文档，不另造材料。
- 这套判断由写作者自己完成，没有工具把关。误收录的材料应移出，并清除悬空引用。
